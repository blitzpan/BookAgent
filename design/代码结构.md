# 代码结构

> 结论先行：**单仓库、双目录（monorepo）**——一个 Git 仓库，内含 `backend/` 与 `frontend/` 两个目录，外加 `design/` 存放设计文档。不拆成两个独立仓库。

---

## 1. 为什么是单仓库

- BookAgent 的代码要同时复用两端：它的 `services/providers/*` 和 `geminiService.ts` 搬到 `backend/`；它的 React `App.tsx`/组件思路改成 `frontend/` 的「管理+查看」界面。两端**共享同一套数据类型**（故事、页、图结构），单仓库直接 `import` 最省事；拆两库就得搞「共享类型包」或复制，徒增麻烦。
- 个人/小团队维护，单仓库部署、版本对齐都简单；真要分也不迟。
- 拆两库的仅有好处是「彻底解耦、各自发版」，对这个项目是过度设计。

## 3. 后端各模块职责

| 模块 | 职责 |
| --- | --- |
| `db/` | SQLite 连接与建表迁移 |
| `services/storyService` | 故事 CRUD、改写（safety→refine→parse）、分页结果落库 |
| `services/characterService` | 抽角色定义 + 生成角色锚图（落盘 sheet 图，写 `characters`） |
| `services/generationService` | 编排一次 run：调用 characterService → 逐页生图+评分 → sequence 评估，离散写库翻状态 |
| `services/directorService` | 封装三个 Director（Frame/Identity/Sequence）与图像安全校验，输出评分 |
| `providers/` | 模型后端，原样复用 BookAgent，仅移除 Vite 注入、改读真实 `process.env` |
| `geminiService.ts` | 原 BookAgent 编排层函数，移植为后端可调（去掉浏览器 `File` 依赖） |
| `worker/taskRunner` | 异步执行 run，支持幂等续跑 |
| `worker/recovery` | 服务启动扫描 `queued/running` 的 run 自动续跑 |
| `storage/imageStore` | 把模型返回的 dataUrl/Buffer 落盘到 `assets/`，返回相对路径 |
| `routes/` | 暴露 REST 接口（见《接口设计.md》） |

## 4. BookAgent 文件如何搬入

| 来源（BookAgent） | 目标（本仓库） | 动作 |
| --- | --- | --- |
| `services/providers/*` | `backend/src/providers/*` | **整目录复制**，移除 `vite.config.ts define` 相关，改读 `process.env` |
| `services/geminiService.ts` | `backend/src/geminiService.ts` | **复制**，把 `File`→`Buffer`、返回 dataUrl 处接入 `imageStore` 落盘 |
| `types.ts` (`StoryPage`) | `backend/src/types.ts` | 复制并扩展为完整实体类型（含默认/备用图、run 等） |
| `App.tsx` 主流程 | `generationService` + `taskRunner` | **重写编排**：原 `handleGenerateClick` 的循环逻辑搬进后端 service，去掉 UI 状态 |
| `App.tsx` UI 组件 | `frontend/src/components/*` | 改写：从「生成器」变为「管理+查看+审批」壳 |
