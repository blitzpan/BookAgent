# 接口设计

> 风格：REST。生图/配音/热区均为**异步任务**：触发后返回 `{ taskId, runId }`（整书生图）或 `{ taskId }`（单页/补画/配音/热区），
> 前端通过 `GET /api/tasks/:taskId` 轻量轮询进度（生图 2s、run 详情 3s），并在活跃任务进行中做温和自动刷新。
> `stories.status` / `generation_runs.status` / `generation_tasks.status+progress` 共同描述进度。

---

## 1. 端点清单

| 方法 | 路径 | 说明 | 是否异步 |
| --- | --- | --- | --- |
| POST | `/api/stories` | 建故事（存原始文本/style/页数） | 同步 → 状态:新建 |
| POST | `/api/stories/:id/rewrite` | 触发改写（产出 refined_text + pages） | 同步（秒级） → 改写完成待生图 |
| GET | `/api/stories` | 故事列表（带 status，按需读） | 同步 |
| GET | `/api/stories/:id` | 故事详情（故事 + 页 + 最新 run 概览） | 同步 |
| POST | `/api/stories/:id/generate` | 带配置触发生图 → 建 `generation_runs` + `generation_tasks(kind=full)` | **异步** → 返回 `{ taskId, runId }` |
| GET | `/api/stories/:id/runs` | 该故事所有 run（状态+进度） | 同步 |
| GET | `/api/runs/:runId` | 某 run 详情（页+默认/候选图+锚图+Sequence评分） | 同步 |
| GET | `/api/tasks/:taskId` | 任务进度轮询（生图/补画/配音/热区共用） | 同步 |
| POST | `/api/pages/:pageId/images` | 为某页生成新图（`manual_new`，追加到当前 run 的候选图） | **异步** → 返回 `{ taskId }` |
| PATCH | `/api/page-images/:imageId` | 设为默认图（翻 `is_default`） | 同步 |
| POST | `/api/stories/:id/publish` | 审批发行 → 状态:审批通过 | 同步 |
| DELETE | `/api/stories/:id` | 软删除 | 同步 |
| GET | `/assets/*` | 静态图片（按 `image_path` 吐文件） | 同步 |

> `redraw`（基于参考图微调）已实现：`POST /api/page-images/:imageId/redraw` 触发重画并把新图追加为候选（与 `POST /api/pages/:pageId/images` 逻辑同源）。

## 2. 关键端点请求/响应示例

### 2.1 建故事
```http
POST /api/stories
{ "original_text": "Once upon a time...", "style": "whimsical cute", "page_count": 6, "user_title": "小熊的故事(可选)" }
→ 200 { "id": 1, "status": "新建" }
```

### 2.2 触发改写
```http
POST /api/stories/1/rewrite
→ 200 {
  "id": 1,
  "status": "改写完成待生图",
  "refined_text": "...",
  "pages": [
    { "page_number": 1, "text_en": "...", "text_zh": null, "image_prompt": "..." }
  ],
  "rewrite_result": { "mode": "good_polish", "feedback": "..." },
  "safety_result": { "isSafe": true, "reasons": [] }
}
```
> 注意：改写只产出 `pages`（文本+image_prompt）与 `refined_text`；**角色锚图在生图 run 时才生成**（见 2.4）。

### 2.3 触发生图（异步）
```http
POST /api/stories/1/generate
{
  "frame_threshold": 0.75, "max_frame_retry": 3,
  "sequence_threshold": 0.8, "max_sequence_retry": 1,
  "initial_retry_budget": 1,
  "text_provider": "ark", "image_provider": "ark", "vision_provider": "ark",
  "aspect_ratio": "4:3", "image_size": "2K"
}
→ 201 { "taskId": 12, "runId": 7 }   ← 立刻返回,不阻塞;进度靠 GET /api/tasks/12 轮询
```
后端动作：建 `generation_runs`（配置快照 + status=queued）+ `generation_tasks(kind=full)`，派发 `taskRunner` 异步执行：
1. 抽角色定义 + 生成锚图（写 `characters.sheet_image_path`）；
2. 逐页：生图 → 安全校验 → 身份 Director + 图文 Director → 存 `page_images`（首跑 1 张默认图）；
3. 跑 `sequence_checks`（只评不修）；
4. 离散翻 `generation_runs.status` → running → completed，更新 `progress`。

### 2.4 查看 run 详情
```http
GET /api/runs/7
→ 200 {
  "run": { "id": 7, "status": "completed", ... },
  "characters": [ { "char_key":"bear", "name":"小熊", "sheet_image_path":"assets/1/anchors/7.png" } ],
  "pages": [
    {
      "page": { "page_number": 1, ... },
      "default_image": { "id": 101, "image_path":"assets/1/1/101.png", "combined_score":0.82 },
      "candidates": [ { "id": 102, "image_path":"...", "combined_score":0.6 } ]
    }
  ],
  "sequence_checks": [ { "is_consistent": true, "score": 0.85, "issues": [] } ]
}
```
> 进度 `progress` 已迁到任务层：`GET /api/tasks/:taskId` 返回 `{ task:{ status, progress:{total,done,failed}, last_error } }`。

### 2.5 为某页生成新图（异步 / 同步上传）
```http
POST /api/pages/1/images
{ "kind": "manual_new" }
→ 201 { "taskId": 13 }   ← 不新建 run,仅为当前版本追加候选图(kind=manual_new),完成后插入 page_images
# 人工补图（不触发图像模型，S15）：带 image(dataURL) 同步落盘并设为默认图
POST /api/pages/1/images
{ "image": "data:image/png;base64,..." }
→ 201 { "imageId": 104 }
```

### 2.6 设为默认图
```http
PATCH /api/page-images/102
→ 200 { "ok": true }   ← 该页 is_default: 102=true, 其他=false
```

### 2.7 审批发行
```http
POST /api/stories/1/publish
→ 200 { "status": "审批通过的作品" }
```

## 3. 状态码与状态语义

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| `stories.status` | 新建 / AI改写中 / 改写完成待生图 / 生图中 / 生图完成待审批 / 生图部分失败 / 待审批发行 / 审批通过的作品 / 删除 | 作品级生命周期 |
| `generation_runs.status` | queued / running / completed / partial_failed / failed / interrupted | 单次执行生命周期 |
| HTTP | 200 同步成功 / 201 异步已接受（返回 `{taskId,runId}` 或 `{taskId}`）/ 4xx 参数错误 / 5xx 服务端错误 | — |

前端判断「可否操作」：
- 仅 `改写完成待生图` 可触发生图；
- 仅 `生图完成待审批` 可「待审批发行 → 审批通过」；
- `partial_failed` 的 run 显示「继续生成」按钮（重新入队续跑）。

---

## 4. 设计约束回顾

1. 异步生成**不轮询**，靠状态字段；前端打开页面时读一次即可；
2. 每个生图动作（整书 or 单页）都对应一个 `generation_run`，产物可追溯；
3. 图片经 `/assets/*` 静态服务访问，路径来自 `page_images.image_path`；
4. `redraw` 接口已实现，触发重画并把新图追加为候选；
5. `generation_tasks.kind` 区分整书(full)/单页补画(single_page)/配音(tts)/热区(hotspot)；单页补画复用该 story 当前版本（current_run_id）的锚图与候选；
6. 所有状态迁移加 `canTransition(from,to)` 守卫（如 `generate` 仅 `改写完成待生图` 可触发、`publish` 仅 `待审批发行` 可触发），防止非法迁移；
7. `/assets/*` 静态服务须做路径穿越过滤（拒绝 `..` 与绝对路径），防止任意文件读取（R11）。
