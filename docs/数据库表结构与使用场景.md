## 0. 一图概览

| 表 | 一句话职责 | 主要写入时机 | 主要读取方 |
| --- | --- | --- | --- |
| `stories` | 作品主记录 + 生命周期状态 | 新建故事、改写、生图状态迁移、发布、软删除 | 管理端列表/详情、reader 书架与详情 |
| `pages` | 改写产出的**分页脚本**（文本 + 生图 prompt） | 改写成功后整体重建 | 管理端详情、reader 文本、生图任务 |
| `generation_runs` | 一次**生成版本**（整书）的记录：状态、参数快照 | 整书生图（首次建，续跑复用） | 管理端「运行记录」、reader 取图（`current_run_id`） |
| `generation_tasks` | 一次**执行**（整书 / 单页补画 / 重画）的记录：进度、状态、错误 | 整书生图、单页补画、重画各建一条 | `GET /api/tasks/:taskId` 轮询、宕机恢复 |
| `page_images` | 每页的**候选图**及其评分，含「哪张是当前默认图」 | 生图闭环内每次尝试、单页补画 | 管理端页面卡片、reader 取默认图、一致性修复 |
| `characters` | 角色锚图（一次整书 run 一套） | 整书生图的角色抽取阶段 | 生图 prompt 参考、管理端锚图画廊 |
| `sequence_checks` | 整书一致性评估结论（挂 run） | 整书生图末段 | 管理端一致性提示 |

磁盘资产不在库内：`data/assets/{story_id}/inspiration.{ext}`（灵感图）、`.../anchors/{id}.png`（锚图）、`.../{page_id}/{image_id}.png`（页图）；库中只存相对 `DATA_DIR` 的路径。

## 3. generation_runs —— 一次生成行为（重点争议表）

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `story_id` | 所属故事 |
| `status` | `running` / `completed` / `partial_failed` / `failed`（进度与重试已迁到 `generation_tasks`） |
| `frame_threshold`、`max_frame_retry`、`sequence_threshold`、`max_sequence_retry`、`initial_retry_budget` | 闭环参数快照 |
| `text_provider`、`image_provider`、`vision_provider` | **实际生效的 provider 名**（含 `MOCK_AI` 与回退结果，见决策项 D） |
| `aspect_ratio`、`image_size` | 出图规格快照 |
| `started_at` / `finished_at` / `created_at` | 时间戳 |

> 已删除字段：`scope`、`target_page_id`、`progress`、`last_error`——「整书 vs 单页」与进度/重试改由 `generation_tasks` 承载（见 §3.1）。

写入时机：
- `POST /api/stories/:id/generate` → 首次建 `createRun(storyId, cfg)` 并写入 `stories.current_run_id`（续跑复用同一 run），再 `createTask(...,'full',cfg)` 异步执行。
- 单页补画 / 重画**不建 run**：只 `createTask(story.id, currentRunId, pageId, 'single_page', cfg)`。
- 进程启动时 `recoverTasks()` 把 `queued/running` 的 task 重新拉起（宕机续跑）。

读取方：
- 管理端「运行记录」：`GET /api/stories/:id/runs`（`ORDER BY id DESC`）。
- reader：`story.current_run_id` → `runs.find(r => r.id === current_run_id)`，缺失才回退「最近一条 `completed`/`partial_failed`」。
- 参数快照用于审计「这次跑用了什么参数」。

⚠ 已识别问题：见下文 P1 / P5 / P7（P1 / P5 / P7 均已落地修复）。

## 3.1 generation_tasks —— 一次执行（重点：run 与 task 分离）

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `story_id` / `run_id` | 所属故事与**版本** |
| `page_id` | `kind=single_page` 时指向目标页，整书为 `NULL` |
| `kind` | `full`（整书）/ `single_page`（单页补画 / 重画） |
| `status` | `queued` / `running` / `completed` / `failed` |
| `progress` | JSON `{total, done, failed}`（**进度归 task，不归 run**） |
| `params_json` | 本次执行使用的生图参数快照 |
| `last_error` | 失败原因 |
| `created_at` / `started_at` / `finished_at` | 时间戳 |

索引：`idx_tasks_story(story_id)`、`idx_tasks_status(status)`。

写入时机：
- 整书生图：`createTask(storyId, runId, null, 'full', cfg)`，同一版本同时只允许一个 `full` 任务。
- 单页补画 / 重画：`createTask(storyId, currentRunId, pageId, 'single_page', cfg)`，**不新建 run**；同页已有进行中任务时返回 409。
- 进程启动 `recoverTasks()` 重新派发 `queued/running` 的任务。

## 7. 典型时序

1. 新建故事 → `stories` 一行（状态「新建」）。
2. 改写 → 写 `refined_text`，**删旧 `pages` 重建**（状态「改写完成待生图」）。
3. 整书生图 → `generation_runs` 一条（写入 `stories.current_run_id`）+ `generation_tasks(kind=full)` 一条 + `characters` 一套 + 每页若干 `page_images` + `sequence_checks` 一条；故事状态「生图中」→「生图完成待审批」或「生图部分失败」。
4. 单页补画 / 重画 → **只建** `generation_tasks(kind=single_page)` 一条 + 该页追加 `page_images`（挂当前 run，**不改默认图、不改故事状态**）；故事尚无版本时 409。
5. 审批发布 → 故事状态「审批通过的作品」，reader 可见。
6. reader 拼书 → `stories/:id` 取文本与 `current_run_id` → `runs` 里取该版本 → `/runs/:id` 取每页 `default_image`。

## 8. 已识别的结构性问题（编号便于评审讨论）

| 编号 | 现象 | 影响 | 候选方案 |
| --- | --- | --- | --- |
| **P1** | `generation_runs` 混合两种 `scope`；reader 取 run 时不区分 scope | reader 可能命中**单页补画 run**（当前因 P2 的页级默认图侥幸没坏；一旦"按 run 过滤候选图"就会大面积缺图） | ① 接口/UI 严格按 scope 分流；② reader 改为只读 `scope=full` 的 run；③ 引入"当前选定 run"指针 |
| **P2** | `is_default` 页级全局 | 第二次整书生图覆盖第一次结果；无法对比/回退 | ① 保持现状 + 提供"清空重跑"出口；② 引入"方案/版本"：`stories.current_run_id` 或独立版本表，发布按方案取图 |
| **P3** | 改写时 `DELETE FROM pages` 重建，`page_images` 外键无级联 | 旧图记录悬挂在已删 page；并发时写向孤儿页 | 改写前显式清理该故事的 `page_images`（或加外键级联 + 事务内完成） |
| **P4** | `getRunDetail` 取候选图只按 `page_id` 过滤，**不按 `generation_run_id`** | 管理端候选区混着历次 run 的图，看不出来源 | 返回时带 `generation_run_id` 让前端分组，或加按 run 过滤的参数 |
| **P5** | `text/image/vision_provider` 三列：存"请求传入值"还是"实际生效值"？ | 当前前端传了但后端从不读取 → 三列是**假数据** | **建议改为"实际生效值"**（由后端按 env 解析后写入），前端不再传 |
| **P6** | `characters` / `sequence_checks` 挂 run，但无"当前使用哪套"指针 | 对比与回退缺少锚点 | 同 P2 的方案② |
| **P7** | 状态机与 run 并发：`生图中 → 删除` 合法；配置可在生图中被改 | 跑到一半故事被删 / 参数被改 | 后端加业务闸门：生图期间拒绝改生成相关配置与破坏性操作 |

### 11.1 `page_segments` —— 每页结构化文本行

### 11.2 `audio_sets` —— 配音方案（语音组）
一个故事可有多组方案（不同人或音色），后台试听后选一组作为正式版。
| 字段 | 说明 |
| --- | --- |
| `id` / `story_id` | 归属 |
| `name` | 方案名（默认 `配音方案 #N`） |
| `status` | `pending` / `generating` / `completed` / `interrupted` / `failed`（interrupted/failed 可续跑） |
| `config_json` | JSON：各 `role`/`lang` 的 `voice` 覆盖 + `langs` |
| `is_selected` | 每 story 仅一个为 1 |

### 11.3 `page_audio` —— 每「方案×分段×语言×场景」一条
| 字段 | 说明 |
| --- | --- |
| `audio_set_id` / `page_id` / `story_id` / `segment_id` | 归属（segment_id NULL=整页合并音频） |
| `lang` | `zh` / `en` |
| `scene` | 同 `role`（narration/dialogue/background/sfx） |
| `audio_path` | `assets/{story}/audio_sets/{set}/{page}/seg_{id}_{lang}.mp3`（命中 `/assets/*`） |
| `voice` / `provider` / `duration_ms` | 实际音色 / `edge-tts-universal` / 时长（ms） |
| UNIQUE | `(audio_set_id, page_id, segment_id, lang, scene)` → 天然支持宕机续传（已有则跳过） |

### 11.4 `stories.selected_audio_set_id`
当前选用方案指针；`selectAudioSet()` 写入；reader `getBookAudio` 据此取分段音频。

### 11.5 接口与流程
- `POST /api/stories/:id/tts`：智能分流（续跑 interrupted/failed 或新建；`forceNew` 强制新建）→ 建 `generation_tasks(kind='tts')` 异步执行。
- `GET /api/stories/:id/audio-sets`：列出方案与进度。
- `POST /api/audio-sets/:setId/select` / `resume` / `DELETE`：选用 / 续跑 / 删除（选用中不可删）。
- `GET /api/stories/:id/book-audio?setId=`：reader 用，返回当前/指定方案的逐页分段与 `audioUrls{zh,en}`。
- `TTS_MOCK=1`：写出静音 MP3，零网络，便于离线联调/测试。
