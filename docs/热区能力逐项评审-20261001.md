## H1 阅读端热区尺寸不可控，变成大面积文字遮罩

**是什么**
- 库里只存中心点 `(x, y)`，明确不存 `w/h`（`backend/src/db/schema.sql:186-187`，注释说明「尺寸由 label 渲染时自动推导」）。
- `label` 存的是**整句中文 + 整句英文快照**：AI 生成时 `${text_zh}\n${text_en}`（`backend/src/services/hotspotService.ts:312`），人工拖拽时同样拼两行（`frontend/src/components/HotspotSettings.tsx:136`）。
- 阅读端把这段整句直接渲染进按钮，且 `white-space: pre-line`（`reader/src/components/PageView.tsx:195-201` + `reader/src/styles/global.css:268`），`maxWidth: 88%`（`:209`），**无 max-height、无 overflow、无 min-width**（`:259-275`）。
- 结果：双语模式下热区是一个横跨最多 88% 页宽、两三行高的黄色虚线文字块。一页 3-4 个分段就是 3-4 个大色块压在插画上。

**影响**：目标用户（儿童/家长）打开书看到的是被文字块盖住的插画，「点图发音」退化成「点文字朗读」；热区互相重叠时点击命中错乱。这是能力 4 唯一**面向最终用户可见**的交付形态缺陷。

**怎么做（两个方案，二选一）**

| 方案 | 内容 | 成本 | 代价 |
|---|---|---|---|
| **H1-a（推荐，纯前端）** | 阅读端热区不显示 label 文本：改成一个 28×28 的圆形图标按钮（波形/喇叭），点击后沿用现成的气泡组件 `PageView.tsx:221-223` 显示文案并播音频；`aria-label` 从 `h.type` 改为「播放第 N 段」 | 1.0 人天 | 失去「扫一眼看到图上有什么词」的能力 |
| **H1-b（动后端）** | `page_hotspots` 加 `w`/`h` REAL NULL 列；编辑器支持拖出矩形框；reader 按 w/h 渲染透明热区（不显示文字） | 3.5-4.5 人天 | 要改 schema + 迁移 + 编辑器 + reader + 两端契约；现有 AI 只产出中心点，`w/h` 需新规则（默认框 or AI 补） |

**验收**（H1-a）：打开一本有 3 个热区的已发布书 → 插画上只有 3 个小圆标，插画主体无大面积遮挡 → 点击圆标，气泡出现且对应分段音频播放 → 键盘 Tab 可聚焦到圆标。

**风险/回滚**：纯前端 + CSS，回滚即还原组件；不影响数据。

## H2 只能「保存本页」，跨页改动静默丢失

**是什么**
- 保存函数签名只接受单个 `pageNumber`，只对当前页提交 create/update/delete（`frontend/src/components/HotspotSettings.tsx:202-263`）。
- `dirty` 是**全局单值**：保存成功后无条件 `setDirty(false)`（`:255`）。
- 翻页按钮无 dirty 拦截（`:349-365`），与「返回」「刷新」的拦截逻辑（`:265-274`）不一致。

**复现**：在第 1 页拖 3 个热区 → 翻到第 2 页再拖 2 个 → 点「保存本页」→ 第 1 页的 3 个热区全部丢失，且界面顶部的「● 未保存」标记消失，用户以为都存了。

**影响**：热区是全书逐页劳动，一次误操作丢一页；且丢失**不可感知**，用户直到回到阅读端才发现。

**怎么做**
1. 保存动作拆成两个按钮：**「保存本页」** / **「保存全部」**。
2. `dirty` 从 `boolean` 改为 `Set<number>`（有改动的页码集合）；顶部徽标显示「● N 页未保存」（`HotspotSettings.tsx:289-296`）。
3. 翻页/返回/刷新的拦截条件从 `dirty` 改为 `dirtyPages.size > 0`，确认文案带上页码：「第 1、3 页有未保存改动，确定返回吗？」
4. 「保存全部」= 对 `dirtyPages` 逐个调现有 batch 接口（`routes/hotspots.ts:110`），**后端不用改**。

**成本**：1.5 人天，纯前端。
**验收**：第 1、3 页各拖一个热区 → 顶部显示「● 2 页未保存」→ 点「保存全部」→ 返回「已保存：新增 2 / 更新 0 / 删除 0」→ 重新进入，两个热区都在 → 不保存直接点返回，弹出确认且列出页码。
**风险/回滚**：纯前端状态改造；batch 接口本就按页提交，分批调用与现状等价。

## H3 无键盘操作路径

**是什么**
- 新增热区依赖 HTML5 drag-and-drop：`draggable` + `onDragStart`（`HotspotSettings.tsx:448-453`）与 `onDrop`（`:121-151`）。
- 移动/删除全是鼠标事件：`onMouseDown` + 挂 `window` 的 `mousemove`/`mouseup`（`:153-191`）。
- 热区 DOM 是 `div`，无 `tabIndex`、无 `role`、无键盘事件（`:392-429`）。

**影响**：纯鼠标才能编辑；无法用键盘做精确微调（拖鼠标调 1px 级位置很痛苦）；屏幕阅读器完全不可用。单人桌面场景下不致命，但「精确调整位置」是热区编辑的日常动作。

**怎么做**
- 热区 div 加 `tabIndex={0}` + `role="button"` + `aria-label`（如「热区：小熊说…」）。
- 选中态已存在（`selectedLid`），直接复用：方向键移动 ±0.5%（按住 Shift ±0.1%），`Delete`/`Backspace` 删除，`Esc` 取消选中。
- 新增：选中右侧分段卡片后按 `Enter`，或点击卡片上的「＋ 放置」按钮（在图上居中放一个默认点再由键盘微调）——**替代拖拽**，同时也顺带解决 H4 的一部分。

**成本**：1.0 人天（若同时做「＋ 放置」按钮则 1.5）。
**验收**：Tab 键能把焦点移到某个热区 → 方向键移动后顶部出现「● 未保存」→ Delete 删除 → 全部过程中不碰鼠标。
**风险/回滚**：新增事件监听，不改动既有鼠标逻辑，可独立开关。

## H4 无触摸支持（移动端 / 平板不可用）

**是什么**：同 H3 的事件源——`onDragStart`/`onDrop` 与 `mouse*` 事件在触屏上均不触发；编辑器布局 `lg:grid-cols-[1fr_320px]`（`:345`）在窄屏会挤成上下两栏但拖拽仍不可用。

**影响**：在 iPad / 触屏笔记本上完全无法编辑热区。

**怎么做**：用 Pointer Events 统一鼠标与触摸（`onPointerDown`/`onPointerMove`/`onPointerUp` 替换现有 `mouse*`），拖拽新增改为「点选分段 → 在图上点一下落点」（tap-to-place），天然兼容触摸。

**成本**：1.5 人天（与 H3 合并做约 2.2 人天，因为都动同一套交互）。
**我的建议：暂缓**。理由：你已确认目标用户是「内部单人创作者 + 桌面」，触屏编辑不是当前场景；H3 顺带提供的「＋ 放置 + 方向键微调」已经能覆盖大部分精确编辑需求，H4 的增量收益低。

## H5 「重新生成热区」清空全部 AI 热区：无二次确认、无成本预告

**是什么**
- 按钮文案在 `aiState === 'done'` 时是「✦ 重新生成热区」（`frontend/src/components/StoryDetail.tsx:274-276`），点击走 `startAiHotspots`（`:229-242`）。
- 该接口 `regenerate: b.regenerate !== false`（`backend/src/routes/hotspots.ts:175`），前端不传 body → `regenerate = true` → 后端**先 `DELETE FROM page_hotspots WHERE story_id=? AND source='ai'`**（`backend/src/services/hotspotService.ts:263-268`）。
- 该按钮**没有二次确认**（对比生图有确认弹窗 `StoryDetail.tsx:745-775`），也没有任何成本/耗时提示。

**影响**：一次误点 = 全书 AI 热区清空 + **重新发起 N 页 × 视觉模型调用**（N = 页数，每次调用都是真实计费的 VISION 请求）。人工热区保留（`source='manual'`），但用户不知道这一点，可能以为全没了而恐慌性重复点击。

**怎么做**
1. `aiState === 'done'` 时点击弹确认框（复用生图确认的样式）：「将清除全部 AI 生成的热区并重新定位，约 N 次视觉模型调用（N = 页数）。人工微调的热区会保留。」
2. 按钮样式从当前「主色 sky」降为次级样式，与「继续生成」区分开。
3. 热区按钮区补一行状态说明：已放置热区数 / 已覆盖页数（数据前端已有——`HotspotSettings` 拉过全本，但**详情页没拉**，需补一次 `listHotspots` 或后端在故事详情带出；建议前端补调一次即可，0.1 人天）。

**成本**：0.5 人天，纯前端。
**验收**：点击「重新生成热区」→ 弹出含页数与「人工热区保留」说明的确认框 → 取消则不发请求（Network 面板无 `auto-generate` 调用）。
**风险/回滚**：仅增加确认步骤，不改变后端行为。

## H6 批量 update / 单条改删不校验 story 归属

**是什么**
- 批量删除**校验**了归属：`DELETE ... WHERE id=? AND story_id=? AND page_number=?`（`backend/src/services/hotspotService.ts:200-204`）。
- 批量更新**不校验**：`if (updateHotspot(id, patch)) updated += 1;`（`:212`），`updateHotspot` 只按 `id` 更新 `page_hotspots`。
- 单条 `PATCH /api/hotspots/:hotspotId`（`backend/src/routes/hotspots.ts:133-150`）与 `DELETE`（`:153-160`）同样只按 `id`，无 story 校验。

**影响**：你已确认是单人内部工具，所以**这不是安全问题**；但它是一个**正确性缺陷**——任何脚本/误传 id 都会改到别的书，且前端目前只用 batch，单条接口是未校验的公开面。

**怎么做**：`updateHotspot(id, patch, storyId?)` 增加可选 `storyId`，SQL 加 `AND story_id = ?`；路由层 PATCH/DELETE 先按 id 查出 `story_id` 再与 `:id` 参数比对（或直接给 service 传 storyId）。当前前端 batch 路径已带 storyId，无需改前端。

**成本**：0.5 人天，纯后端。
**验收**：用故事 A 的 id 调 `PATCH /api/hotspots/<B 的热区 id>` → 返回 404 而非 200；正常改自己故事的热区仍成功。
**风险/回滚**：新增 `WHERE` 条件；现有合法调用路径都带 storyId，无兼容问题。

## H7 点击热区的音频与整页播放列表不互斥 → 声音叠加

**是什么**
- 整页播放用 `audioRef` 持有当前 Audio（`reader/src/components/PageView.tsx:78,99-100`）。
- 热区播放**另起炉灶**：`playHotspotAudio` 内部 `new Audio(urls[i])`，全程不读也不暂停 `audioRef`（`:147-167`）。
- 切页时只 `pause()` 不释放（`:86-90`），热区音频实例更是无人持有。

**影响**：自动播放中途点热区 = 旁白与热区音频同时响；连续点几个热区 = 多条音频叠加。这正是你项目目标里「音频状态管理：避免多段音频重叠」（`docs/项目定义与目标.md:41`）明确要求而没做到的点。

**怎么做**：`playHotspotAudio` 首行加 `audioRef.current?.pause(); setPlaying(false);`（把主播放停掉）；并把热区实例也交给 `audioRef` 管理，或在 `playNext` 里维护局部数组以便后续停止。

**成本**：0.2 人天，纯前端(reader)。
**验收**：点「▶」开始整页播放 → 播放中点击任意热区 → 主旁白立即停止，只有热区音频在响 → 再点「▶」能恢复正常播放。
**风险/回滚**：改动集中在 `PageView.tsx` 一个函数内。

## H8 只能创建音频热区，`text`/`link` 是死能力

**是什么**
- 库支持 `kind` ∈ `audio`/`text`/`link`（`backend/src/db/schema.sql:189`），路由也校验 `ALLOWED_KINDS`（`backend/src/routes/hotspots.ts`）。
- 阅读端三种都实现了：`audio` 发音、`text` 弹气泡、`link` 开新标签（`reader/src/components/PageView.tsx:169-173`）。
- 但编辑器**只能产出 audio**：新增时硬编码 `kind: 'audio'`（`frontend/src/components/HotspotSettings.tsx:143`），无 kind 选择、无 `payload` 输入；AI 生成也写死 `'audio'`（`backend/src/services/hotspotService.ts:316`）。

**影响**：不是 bug，是**未被使用的能力**。对儿童绘本来说「点图弹出名词解释」或「点图跳链接」价值未经你验证。

**我的建议：不做**。理由：没有需求方，做了就是猜测；字段与阅读端都已就绪，将来要加是 1.5 人天的纯前端增量，不现在付。

## H9 AI 跳过的页静默无声，无「哪些页还没热区」视图

**是什么**
- AI 生成时有三类跳过：续跑时已有 AI 热区的页（`:289-293`）、无默认图或无分段的页（`:298-302`）、AI 返回空框（`:306-308`）。
- 进度回调只报 `done`/`total`（`:283-286,541`），`skipped` 与 `failed` 只有总数（失败数塞进 `last_error`，`hotspotService.ts:546`），**跳过数完全不上报**。
- 编辑器页导航只显示「第 N / M 页」（`HotspotSettings.tsx:356-358`），没有该页热区数量的标记；详情页的热区按钮也不显示覆盖率。

**影响**：一本 12 页的书，AI 实际只放了 7 页的热区（例如 5 页生图失败没图），用户看到的却是「热区生成完成」，没有任何信号告诉他还有 5 页是空的——直到在阅读端翻到那几页发现点不了。

**怎么做（纯前端即可）**
1. 编辑器加载时已拉全本 `listHotspots`（`HotspotSettings.tsx:60-63`），按 `page_number` 聚合成 `Map<number, number>`。
2. 页导航每个页码旁加小徽标：「第 3 / 12 页 · 2 个热区」或「· 无热区」（后者用琥珀色）。
3. 上一页/下一页按钮改成「跳到下一个无热区的页」的快捷入口。
4. 详情页热区按钮下方显示「已覆盖 7 / 12 页」。

**成本**：1.0 人天，纯前端。
**验收**：AI 生成后若有页被跳过 → 编辑器页导航显示琥珀色「无热区」→ 点「下一个无热区页」能直接跳过去 → 手动补一个热区保存后徽标变绿。
**风险/回滚**：纯展示层；后端字段已齐全（`source`/`confidence`），无需改动。

## H10 编辑完无法直达阅读端验证

**是什么**
- 热区编辑器是 `App.tsx:60-64` 切换的独立全屏视图，没有指向 reader 的出口。
- reader 是独立应用（`reader/vite.config.ts` 端口 5173，与生成端 5174 不同），且 `VITE_API_BASE` 默认硬编码 `http://localhost:3000`（`reader/src/api/client.ts:7`）。
- 发布后才进书架（`reader/src/api/client.ts:51-53` 只取 `审批通过的作品`）。

**影响**：改完热区要手动另开一个端口、找到书、翻到对应页才能验证，反馈闭环断裂——这是热区迭代慢的直接原因。

**怎么做**：编辑器顶部加「在阅读器中预览」按钮，`href` 指向 `${READER_BASE}/book/${storyId}`，`READER_BASE` 由 `frontend/vite.config.ts` 的 `define` 注入（开发环境 `http://localhost:5173`），未配置时按钮隐藏。

**成本**：0.5 人天，纯前端。
**验收**：编辑器点「预览」→ 新标签打开阅读端对应书 → 能看到刚保存的热区位置 → 点击能发音。
**风险/回滚**：新增环境变量，未配置时按钮不渲染，零副作用。
