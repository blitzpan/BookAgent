# 变更设计：生图配置与生成任务（已批准并编码完成，见 §8）

> 目标：**配置归配置、动作归动作**；**一个故事当前只有一个生成版本**；**单页补画不产生新版本**；任务执行与版本产物的职责彻底分离。
> 前提：开发阶段，无正式数据，库可删重建，不做迁移脚本；只做"正确的实现"，不以工作量为取舍依据。
> 已落地但需随之调整：故事文本 tab、故事配置面板、`PATCH /api/stories/:id`、故事列表分页表格。

---

## 1. 核心设计：三层职责分离

| 层 | 表 | 职责 | 不负责 |
| --- | --- | --- | --- |
| **配置层** | `stories.generation_config` | 这个故事"想怎么生成"（参数意图） | 不记录执行过程 |
| **任务层** | `generation_tasks`（新） | 每次**异步执行**：状态、进度、错误、本次参数、并发去重、宕机恢复 | 不代表产物归属 |
| **版本层** | `generation_runs` | 一次**整书生成的结果（版本）**：产物归属 + 版本参数快照 + 产出状态 | 不再承载进度/重试/恢复 |

一句话：**产物=page_images，版本=run，执行=task**。补画只是"往当前版本里加图"，因此不建 run、只建 task。

## 2. 变更总览

| # | 类别 | 变更 | 为什么 |
| --- | --- | --- | --- |
| C1 | 数据 | `stories` 增 `generation_config TEXT`（JSON） | 生图参数归属故事，字段易变，避免频繁加列 |
| C2 | 数据 | `stories` 增 `current_run_id` | 标明当前生效版本，reader 与发布据此取图 |
| C3 | 数据 | `generation_runs` 删 `scope` / `target_page_id` | 只剩整书一种 run，留着是永久噪音 |
| C4 | 数据 | `generation_runs` 删 `progress` / `last_error` | 进度与错误是**执行**属性，归 task；一处进度避免双写不一致 |
| C5 | 数据 | `generation_runs.status` 收窄为 `running / completed / partial_failed / failed` | `queued` 是任务属性；`interrupted` 由 task 层恢复机制取代 |
| C6 | 数据 | `generation_runs` 三列 provider 语义改为「实际生效值」 | 现在存的是前端传的值而后端从不读取，是假数据；改为留痕"这次用的哪个模型" |
| C7 | 数据 | 新增 `generation_tasks`（统一任务层） | 所有异步执行统一承载：整书生成、单页补画、将来的批量重画 |
| C8 | 数据 | `page_images` 增 `task_id` | 每张图可归因到"哪次执行产出"，审计闭环 |
| C9 | 数据 | `page_images.is_default` 改为「(page_id, run_id) 各一张」 | 现在是页级全局，第二版会翻掉第一版的默认图，无法对比/回退 |
| C10 | 数据 | `characters` 改为按 run 取 | 现在按 story 复用，将来版本 B 会串用版本 A 的锚图 |
| C11 | 数据 | 改写前清理该故事 `page_images` | 改写会 `DELETE pages` 重建，旧图悬挂在已删 page 上 |
| C12 | 后端 | `POST /generate` body 变为可选覆盖，缺省读 `generation_config` | 实现"先配置、后生图"；保留覆盖能力以兼容脚本与测试 |
| C13 | 后端 | 任务层驱动：整书/补画都建 task，返回 `taskId` | 执行状态只有一处真相；并发去重、进度、恢复统一 |
| C14 | 后端 | 续跑 = 同一 run 上**再建一个 full task** | run 不变 → 幂等判定仍按 run 走 → **只补未成功的页**，不重画全部、不覆盖已有默认图 |
| C15 | 后端 | 状态机去掉「生图完成待审批 → 生图中」 | 前端禁用可被绕过，用 `assertStoryTransition` 做真闸门 |
| C16 | 后端 | 生图期间拒绝改生成相关配置；`user_title` 仍可改 | 防止跑到一半改参数/画风；标题不参与生成，不该被锁 |
| C17 | 后端 | 补画：无当前 run 则 `409`；否则建 `single_page` task，产物挂当前 run | `page_images.generation_run_id` 为 NOT NULL，必须有归属版本 |
| C18 | 后端 | 启动恢复改为扫描 `queued/running` 的 task（按 kind 分派） | 恢复的对象是"执行"，不是"版本" |
| C19 | 后端 | `getRunDetail` 默认图/候选图按 run 隔离并带 `run_id`/`task_id` | 现在候选区混着历次 run 的图，看不出来源 |
| C20 | 后端 | reader 取图按 `current_run_id` | 现在 reader 取"第一条 completed 的 run"，多版本后会取错 |
| C21 | 前端 | 生图参数并入「故事配置」面板，7 项带中文说明；删除模型三下拉 | 现在只有干标签看不懂；模型下拉后端不读，是假控件 |
| C22 | 前端 | 「生图」按钮纯动作化：配置摘要 + 次数估算 + 二次确认；进度取自 task | 配置与动作分离后，点之前应知道用哪套参数、最多生成多少次 |

## 3. 数据模型最终形态

### 3.1 `stories`（+2）
```
+ generation_config TEXT     -- JSON 生图参数，创建时写默认值
+ current_run_id    INTEGER  -- 当前生效版本（run）
```
`generation_config` 键（7 项，provider 不在此）：
`frame_threshold / max_frame_retry / sequence_threshold / max_sequence_retry / initial_retry_budget / aspect_ratio / image_size`

约定：
- 创建故事时由**后端**写默认值（单一来源，前端不再硬编码）。
- 读取 `merge(默认值, 解析结果)`；NULL 或字段缺失都走默认值。
- 写入做白名单 + 范围校验，未知键忽略。区间：阈值 `frame_threshold`/`sequence_threshold` 0–1；`max_frame_retry`/`initial_retry_budget` 1–10；`max_sequence_retry` **0–5**（见 `backend/src/constants/generationConfig.ts`）。
- `PATCH` 语义为**部分 merge**（只覆盖传来的键）。

### 3.2 `generation_runs`（−4 列，语义收窄）
```
- scope, target_page_id, progress, last_error
  status  → running / completed / partial_failed / failed
  frame_threshold ... image_size          -- 版本参数快照（保留）
  text_provider / image_provider / vision_provider  -- 改为「实际生效值」
  started_at / finished_at / created_at   -- 版本时间线
```

### 3.3 `generation_tasks`（新增）
```
id, story_id, run_id, page_id NULL,
kind        -- 'full' | 'single_page'（将来可加 'repair_failed' 等）
status      -- queued / running / completed / failed
progress    -- JSON {total, done, failed}
params_json -- 本次执行参数快照（可覆盖版本参数）
last_error, created_at, started_at, finished_at
索引：idx_tasks_story(story_id)、idx_tasks_status(status)（无 run_id 独立索引）
```
同一 `run_id` + `kind` 只允许存在一个 `queued/running` 的 task（并发去重在应用层校验）。

### 3.4 `page_images`（+1，语义改动）
```
+ task_id
  is_default → 同一 (page_id, run_id) 内唯一
```
整书生成的图挂该 run + 该 task；补画的图挂**当前 run** + 补画 task。

### 3.5 `characters`
`ensureAnchors(storyId, runId)` 改为按 run 查询，无则抽取并挂该 run（现状按 story 复用）。

### 3.6 `pages`
改写流程改事务：`DELETE page_images WHERE story_id=?` → `DELETE pages` → `INSERT pages`。

## 4. 后端行为

### 4.1 参数来源（C12）
```
cfg = merge(stories.generation_config, req.body || {})
```

### 4.2 生图 / 续跑（C13–C15）
- **首次生图**：建 run（写参数快照 + 实际 provider）→ 建 `full` task → 返回 `{ taskId, runId }` → `current_run_id` 指向该 run。
- **继续生图**（故事状态 `生图部分失败`）：**同一 run 上再建一个 `full` task**，run.status 回 `running`。因为幂等判定是 `WHERE generation_run_id=? AND page_id=? AND is_default=1`，已有默认图的页直接跳过 → **只补失败页**，不重画、不覆盖。
- **完成后禁止再整书生图**：状态机移除「生图完成待审批 → 生图中」；另加任务层闸门（同 run 已有 active task → 409）。
- **不提供"清空重跑"出口**（已决策）：完成后如需重做，删除该故事重建。

### 4.3 单页补画（C17）
1. 取 `current_run_id`（无 → `409`）。
2. 建 `single_page` task（同页已有 active task → `409`，防重复点击）。
3. 异步执行：参数取所属 run 的快照，`frameBudget` 用 `max_frame_retry`（补画属重试语义；首跑才用 `initial_retry_budget`），`flipDefault=false` 只追加候选。
4. 产物写入 `page_images`，挂当前 run + 该 task。

### 4.4 任务驱动与恢复（C18）
`taskRunner` 改为以 task 为单位：按 `kind` 分派 `runFullGeneration` / `runSinglePage`；`running` 去重集合改按 taskId。启动扫描 `queued/running` 的 task 重新拉起。run 不再参与恢复。

### 4.5 生图期锁定（C16）
`PATCH /api/stories/:id` 在「故事状态 = 生图中，或存在 active task」时：拒绝 `generation_config` 全部键、`style`、`target_page_count`、`inspiration_image`；允许 `user_title`。前端同步禁用「改写 / 生图 / 删除 / 发布」。

### 4.6 默认图与 reader（C9 / C19 / C20）
- `setDefaultImageForPage` 只在本 run 内切换：`UPDATE page_images SET is_default=0 WHERE page_id=? AND generation_run_id=?`。
- `getRunDetail`：`default_image` 取该 run 的；候选带 `run_id` / `task_id` 供分组。
- `/api/stories/:id` 返回 `current_run_id`；reader 按它取该 run 的默认图。

### 4.7 provider（C6）
后端暴露解析出的 provider 名（`pick()` 目前只返回实例不返回名字），`createRun` 写入三列。**不改变现有回退行为**（D4 决策：provider 来自配置，正常运行不会配错）。

## 5. 前端

### 5.1 故事配置面板（C21）
新增「生图参数」分组，7 项，每项中文名 + 一行说明，默认值由后端下发（文案不写死数字）。说明采用 `docs/BookAgent简介与配置说明.md` 3.4 节已有描述。
- 质量阈值：帧阈值（单页验收分数线，取身份一致性/图文匹配的较低者）、序列阈值（整书一致性分数线）
- 重试预算：首跑每页尝试次数、单页最大重画次数、最大序列修复轮数
- 出图规格：比例、尺寸

删除：文本模型 / 图像模型 / 视觉校验 三个下拉。

### 5.2 生图按钮（C22）
| 故事状态 | 表现 |
| --- | --- |
| 新建 / 改写完成待生图 | 「开始生图」可点 |
| 生图中 | 禁用，显示 task 进度 `done/total` |
| 生图完成待审批 / 待审批发行 / 审批通过的作品 | 禁用，提示"已生成；如需重做请删除故事重建" |
| 生图部分失败 | 「继续生图」（同一版本只补失败页） |

点击弹确认：参数摘要 + 估算"最多约 N 次生成"。

### 5.3 运行记录与补画
- 运行记录 = 版本列表（整书 run）：id / 状态 / 时间 / 参数摘要 / 当前任务状态与进度。
- 补画进度与结果挂在页卡片内（补画中 / 失败 / 已追加候选），不再出现在运行记录。

## 9. 已决策记录

| 项 | 结论 | 理由 | 后续影响 |
| --- | --- | --- | --- |
| D1 run 冗余列 | 删除 `scope`/`target_page_id` | 只剩整书一种 run，保留即噪音 | 将来若 run 要多用途，加回即可 |
| D2 任务载体 | **统一任务层**（不改工作量优先） | 职责彻底分离：产物=page_images、版本=run、执行=task；进度/恢复/并发去重只有一处真相；续跑天然只补失败页 | 短期存在"版本"与"任务"两个概念需前端区分展示 |
| D3 清空重跑 | **不做** | 成品生成后即冻结 | 想换画风/重做只能删除故事重建（原稿与配置一并丢失）；将来若要加，成本≈1 个删除接口 |
| D4 provider 容错 | **不额外处理** | provider 来自配置，正常运行不会配错 | 保留现有静默回退行为；仅把实际生效值落库做审计（C6） |
